# 재시도 결과와 복구 방법

2026-10-19 현재 환경에서 실제 셸 실행·의존성 설치·로컬 Worker/SQLite D1/DO 실행과 브라우저 연결이 가능해졌다. 과거의 모든 재시도가 같은 이유로 실패했다는 증거는 없으며, 아래 두 문제를 구분해야 한다.

## 1. 실행 환경 자체의 실패

이전 시도에서는 명령이 셸에서 실행되기 전에 환경 capability/ERS 초기화 대기·시간 초과가 나타났다. 이는 애플리케이션의 빌드 오류와 구분되는 플랫폼 실행 단계 문제다. 현재는 같은 실행 단계가 정상 동작한다. 플랫폼 내부 로그에 접근할 수 없으므로 정확한 서비스 장애 원인이나 복구 계기를 단정하지 않는다.

다시 셸 실행 전부터 멈춘다면 환경 준비 상태를 먼저 확인하고 초기화가 끝난 뒤 재시도한다. 준비가 끝나도 동일하다면 환경을 재시작하거나 새 환경을 만들어 플랫폼 지원에 발생 시각(UTC), 환경 식별자, 실행 전 오류 메시지를 전달한다. 게임 코드 수정이나 npm 재설치는 셸 자체가 시작되지 않는 문제를 해결하지 못한다.

## 2. 환경은 시작됐지만 소스와 데이터가 없음

이번에 `/workspace/yangjigo`는 `work` 심볼릭 브랜치가 있는 유효한 Git 저장소지만 HEAD 커밋과 앱 소스가 없었다. 기존 `.wrangler` 계정 데이터도 없었다. 인증된 `git ls-remote --heads origin`은 성공했지만 브랜치 목록이 비어 있었다. GitHub 인증 오류라고 판단할 근거가 없으며, 원격에 보존된 소스가 없어서 다시 내려받을 코드도 없었다.

저장돼 있던 환경 설정에는 설치·실행 지침이 있었으나, 지침은 사라진 애플리케이션 파일이나 DB를 생성하는 백업이 아니다. 이전 미커밋 파일이 왜 스냅샷에 남지 않았는지는 확인할 수 없다. 과거 계정을 복구했다고 주장하지 않는다.

대화 기록과 사용자가 첨부한 요구사항을 바탕으로 현재 v0.3 소스를 다시 구현했다. 이는 이전 파일의 바이트 단위 복구가 아니다. 실제 원본 요구사항은 `docs/REQUIREMENTS.md`로 보존했다. 노말 완주 티켓, 전원 하드 입장, 구매/장착 등은 새 구현에서 검사한다.

## 복구와 예방

1. 현재 소스 백업 `/workspace/sejong-source-v0.3.0.tar.gz`를 내려받아 외부에 보관한다. 이 백업은 코드·SQL·lockfile·문서를 포함하고 node_modules·세션·DB·비밀값은 제외한다.
2. 빈 디렉터리에 압축을 풀고 `npm ci --no-audit --no-fund`, `npm run db:migrate`, `npm run dev` 순서로 실행한다. 압축 안의 README가 기준이다.
3. 지속 개발하려면 검토한 로컬 커밋을 GitHub 원격에 게시해 다음 환경이 가져올 수 있도록 한다. 이번 작업에서는 원격 푸시를 하지 않는다. 로컬 커밋·소스 압축 파일은 현재 작업 공간에 있으므로 외부 보관 전에는 다음 환경의 복원을 보장할 수 없다. 현재 체크아웃의 커밋을 검토하고 올리기로 결정했다면 `git push origin HEAD:main`으로 게시할 수 있다. 강제 푸시는 필요하지 않다.
4. 클라우드 환경 설정에서 저장된 설치/시작 지침을 검토·저장한 후 환경을 Publish한다. 설정 초안 저장은 적용·배포·새 작업 복원 검증과 다르다. 특히 로컬 전용 커밋 복원은 보장되지 않는다.
5. 계정 데이터는 별도로 안전하게 백업한다. 기존 계정이 필요하면 예전 `.wrangler` 저장소 또는 원격 D1 백업이 필요하다. 현재 새 DB에는 과거 사용자·진행 기록이 없다.

## 실행 단계별 점검

| 증상                           | 확인                             | 조치                                 |
| ------------------------------ | -------------------------------- | ------------------------------------ |
| 셸 시작 전 초기화 시간 초과    | 환경 준비/실행 도구 상태         | 환경 재시작·플랫폼 장애 문의         |
| package.json 없음              | 소스 파일과 실제 HEAD, 원격 refs | 백업 또는 게시된 커밋 복원           |
| npm 캐시·설정 쓰기 거부        | 홈 디렉터리 권한                 | README의 `/tmp` 캐시/설정 사용       |
| D1 테이블·열 없음              | 적용된 마이그레이션              | `npm run db:migrate`, DB 삭제 금지   |
| 화면은 있으나 인증 API가 안 됨 | 정적 서버만 실행했는지           | `npm run dev`로 Worker까지 실행      |
| Playwright 실행 파일 없음      | Chromium 설치·실행 경로          | 시스템 Chromium 또는 Playwright 설치 |
| 하드 입장 거부                 | 전원의 해당 에피소드 티켓        | 노말 완주로 획득 후 대기실 새로고침  |
| 옛 계정 로그인 불가            | 과거 계정 DB 존재 여부           | 별도 DB 백업 복원; 소스만으론 불가   |

개발 중 발견한 대기실 오류 메시지 소실 문제도 수정했다. 스냅샷으로 화면을 다시 그려도 메시지의 표시 시간을 유지한다. 테스트의 대기실 미리보기 canvas와 게임 canvas가 겹쳐 생긴 선택자 모호성은 게임 영역으로 선택자를 좁혀 해결했다.
