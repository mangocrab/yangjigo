# 실제 구현 구조

브라우저의 HTML UI와 Phaser 렌더러는 같은 Worker의 정적 파일을 사용한다. Worker는 D1 기반 인증·프로필·상점 API를 제공하고, 인증된 방 요청만 해당 GameRoom Durable Object로 전달한다. Lobby Durable Object는 방 목록을 관리한다. 세종-1/세종-2는 논리적 채널이다.

## 입력과 시뮬레이션

`src/shared/protocol.ts`의 버전 1 명령만 허용한다. 클라이언트는 방향·공격·스킬·상호작용을 보내며 좌표·HP·보상 값을 지정할 수 없다. `src/server/simulation.ts`가 격자 충돌, 140ms 이동, 공격 간격, 스킬, A\* 좀비 경로, 공동 임무와 결과를 결정한다. `src/shared/content.ts`에 맵과 목표, `rules.ts`에 에피소드·난이도·스킨 정의를 둔다.

게임 DO는 활성 연결이 있을 때 35ms 간격으로 상태를 계산하며 변화가 있을 때 스냅샷을 보낸다. 클라이언트는 최대 60FPS로 위치를 보간한다. 소켓당 메시지 제한은 초당 40개, 명령은 512자 이하이다. 연결이 모두 끊기면 타이머를 멈추고, 재접속 때 방어 종료 시간을 끊긴 기간만큼 늦춘다. 상태는 중요한 명령 직후 및 활성 중 약 2초마다 DO 저장소에 보존한다.

WebSocket은 Hibernation API를 사용하지만 활성 게임의 타이머에는 실행 비용이 발생한다. 입력 없는 대기실에서는 주기 입력을 보내지 않는다. 끊긴 참가자는 약 60초 재접속 유예 후 정리하고, 방장을 연결된 참가자로 이전한다. 빈 방은 alarm에서 삭제한다. 공개 목록은 TTL 120초이며 게임 중 신규 참가는 차단한다.

## 인증과 소유권

PBKDF2-SHA256 100,000회, 사용자별 무작위 salt를 사용한다. 이는 현재 Workers 구현의 반복 제한을 고려한 프로토타입 설정이다. 공개 운영 전 비밀번호 해싱 정책을 검토해야 한다. 무작위 256비트 세션 토큰의 해시만 D1에 저장한다. 쿠키는 HttpOnly·SameSite=Strict이며 HTTPS에서 Secure를 붙인다. 루프백 HTTP 개발만 예외다. 상태 변경 및 WebSocket 요청은 동일 Origin을 요구한다. SQL은 바인딩 파라미터를 사용한다. 가입/로그인은 IP·계정 기준 10분 30회, 방 생성은 사용자 기준 10분 8회로 제한한다. 비밀번호 복구는 제공하지 않는다.

## 티켓·보상·구매 원자성

D1에는 계정과 장기 기록, DO에는 현재 게임 상태를 저장한다. `stage_records`의 `(run_id,user_id)` 유일 키와 트리거로 보상·클리어 횟수·티켓을 한 번만 반영한다. 중간 스테이지 이동은 보상을 주지 않는다. 마이그레이션 0003은 과거 기록을 `legacy`로 분류해 노말 티켓을 소급 발급하지 않는다.

하드 입장은 DO에서 권한·전원 준비·접속을 검증한 다음, 새 입장 ID가 있는 후보 상태를 DO에 먼저 저장한다. D1 `hard_entries`의 삽입 트리거가 해당 에피소드에 대한 전원의 티켓을 검사하고 모두 차감한다. 부족하면 단일 문장 전체가 취소된다. 같은 입장 ID는 차감이 반복되지 않는다. 후보 상태가 남은 채 재시작되면 같은 ID로 결제를 재시도하고 게임 상태를 확정한다. 재시도 명령은 기존 입장 ID를 유지한다. D1/DO 간 분산 트랜잭션 대신 저장된 준비 단계와 멱등성을 사용한다.

구매는 `(user_id,request_id)` 영수증을 삽입하며 DB 트리거가 서버 상품 가격·소유권·잔액을 검사하고 재화 차감과 인벤토리 등록을 원자적으로 처리한다. 동일 요청 ID 재전송은 다시 차감하지 않고, 다른 상품에 재사용하면 거부한다. 장착은 보유 스킨만 허용한다. 클라이언트 표시 잔액은 권한 근거로 사용하지 않는다.

## 파일

- `src/client`: 화면, 입력, 픽셀 아트, Phaser 장면.
- `src/server`: Worker 라우팅, 인증, 경제, 디렉터리/방 DO, 순수 시뮬레이션.
- `src/shared`: 직업·주연·감염자·스테이지·난이도·타입·프로토콜·컷신 대사.
- `migrations`: 기존 데이터를 보존하는 순차 D1 SQL.
- `tests`: 순수 시뮬레이션·실제 SQLite 트리거·브라우저 통합 검사.

아직 원격 배포·요금 측정·대규모 동시접속 부하 검증은 하지 않았다. 채널 UI에는 고정된 접속 가능 안내만 있으며 실제 전체 접속 인원·혼잡도 모니터링은 후속 작업이다.

## v0.4 스토리 상태

실시간 플레이어에 `weaponAcquired`·`rockHits`, 적에 `kind`, 게임에 `cutscene`(장면 ID·종류·확인 사용자 목록)을 저장한다. DB 테이블 변경 없이 DO 스냅샷에 보존한다. 체크포인트에도 무기/튜토리얼 상태를 포함한다. 에피소드 0은 시작 시 무기 상태를 초기화하고 장비함에서 서버가 수령을 승인한다. 현재 에피소드의 강화 명령은 항상 거부한다.

`scene-done`은 소켓의 사용자 ID와 현재 장면 ID를 검사한다. 중복 확인은 한 번만 반영하고 이전 장면의 ID는 거부한다. `tick`은 접속 중인 전원이 확인할 때까지 이동·공격·적 AI를 실행하지 않는다. 입력 패킷 역시 장면 중에는 저장하지 않아 종료 후 눌린 입력이 이어지지 않게 한다. 마지막 컷신 확인 후에만 `clear`로 바뀌어 기존 멱등 보상 처리가 작동한다. 장면 상태는 일반 방 저장소와 함께 저장되며, 연결이 끊긴 사용자 때문에 대기가 고정되지 않는다.
